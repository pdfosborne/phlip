2. Typography

One typeface, used two different ways: plain and legible for reading, structured and emphasised for numbers.

Atkinson Hyperlegible

Braille Institute · free, open · weights used: 400, 700

Cinema night, Sci-fi double bill, 7:30pm, by Priya, Check conflicts

Why this font: chosen over conventional app-UI sans fonts (Inter, Plus Jakarta Sans) specifically because it was engineered from vision-science research rather than picked for visual style — "we obsess over clarity" is the actual brand story here, not an accessibility afterthought. The trade-off is a more clinical feel at rest, which is why colour, shape, and the numerals system below carry the warmth instead of the typeface itself.

Calendar dropdown — compact / expanded

Replaced the week-pill entirely (see the "Deliberately excluded" note below). This dropdown is the date-navigation surface for the current group timeline; the separate My calendar sidebar is the user’s cross-group confirmed schedule. Two states: a quiet dot/line overview, and an expanded view showing actual event names. Toggle the chevron below to see both.

Purple meaning dark purple dot/line/bar = at least one accepted event that day — not tied to which date is selected, same signal the timeline itself uses   Week-boundary bug (real one, not cosmetic) grid items default to min-width:auto, which lets unbroken event-label text force a column wider than its fair 1/7 share even with overflow:hidden set — min-width:0 on the cell is the actual fix   Multi-day continuity a bar only gets rounded corners at the event's true start/end — a row-wrap edge (Mon/Sun) stays square, so it reads as "cut off, continues" rather than a second separate event   Gap-bridging cells carry 1px horizontal padding for the date number, which left a visible 2px seam between adjacent bar segments — fixed with margin:-1px on the bar by default, overridden back to a positive inset only on true boundaries

My calendar sidebar — cross-group schedule + timeline bridge

A narrow right-hand comparison rail answering “what am I signed up to?” across every group. The month is always visible; selecting a date updates a compact read-only agenda below it. Cross-group events never navigate away from the current group. One predictable “Show in timeline” link moves the current group timeline to the selected date. The sidebar also supports adding lightweight personal commitments in place, without pulling the user away from a group decision.

Four stages — anticipation, reward, transition, celebration — landing in under 1.5s total, with the row already interactive again well before that. Built from research into successful micro-interaction design, then debugged against several real continuity bugs that only showed up once it was live.

Anticipation

Native :active press — the circle squashes to 0.93 scale. No JS, no delay; the browser's own press state does this for free.

Reward

A flat periwinkle wash floods outward from the button's actual computed position (not a fixed corner) via an expanding clip-path circle — a genuine even fill, not a fading gradient. Checkmark draws on via SVG stroke animation. A real two-tone chime plays (Web Audio, 660Hz→880Hz).

3

Transition

Card shrinks into the mini-card while the external time label expands open in the same breath — the growing time label is what physically pushes the icon rightward, via ordinary flexbox, not manual position math. The shrinking box carries the wash's periwinkle colour forward on its own border/fill, so the colour never disappears mid-motion. The icon itself doesn't appear until the box has fully settled — no intermediate position for it to jump from.

520ms
4

Celebration — "minting"

A white glint sweeps once across the settled icon, synced to start at the same instant the periwinkle colour fades back to neutral — one combined "sealing" moment, not two sequential ones. A confetti/particle version was prototyped and deliberately dropped: it read as generic "fun," where the glint reads as "this now has value" — a closer match to the brand's exclusivity note than confetti ever was.

480ms, overlapping
Real bugs found building this, worth remembering: (1) a radial gradient was tried first for the wash — it fades to transparent before reaching the edges, so it can never actually fill the card evenly; switched to a flat colour revealed by the clip-path instead. (2) Hiding the wash only after the shrink began let its clip-path keep re-interpreting against the shrinking box's changing size, reading as a second uncontrolled swipe — fixed by hiding it the instant the shrink starts. (3) Revealing the icon partway through the shrink and centring it there meant it kept "chasing" the box as it continued resizing — fixed by not revealing the icon at all until the box has fully settled. (4) The final mini-card sits inside .event-row-compact's own 6px left padding, which the shrinking placeholder didn't account for — fixed by animating a matching 6px margin-left into the shrink itself, rather than letting the two layouts disagree at the handoff.
